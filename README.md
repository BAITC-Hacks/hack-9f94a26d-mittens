# Аким на 5 часов

Городской симулятор на TanStack Start. Полноэкранная карта 2ГИС показывает пять игровых районов: Есиль, Алматы, Сарыарка, Байконур и Нура. Алматы включает геометрическое объединение Алматы и Сарайшыка без внутренней границы. Это группировка сценария, не административное изменение.

## Запуск

Нужен Node.js 22.12+.

```bash
npm install
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Фронтенд и расчётный backend работают на одном сервере; отдельный сервис на порту 8000 не нужен.

В `.env.local` задайте `VITE_2GIS_MAP_KEY` с доступом к MapGL и Places API, включая `items.geometry.selection`. Браузерный ключ виден клиенту: ограничьте разрешённые домены в кабинете 2ГИС. Файл исключён из Git. После изменения переменных перезапустите сервер.

`OPENAI_API_KEY` — необязательный серверный ключ для текстового объяснения результата. Без него численный расчёт работает, а интерфейс сообщает, что AI-анализ недоступен. Ключ не должен иметь префикс `VITE_`.

## Интерфейс и раунд

- Выберите район на карте, по подписи или кнопке над картой.
- Слева направления раскрываются в десять отдельных показателей: T1/T2, E1/E2, S1/S2, B1/B2, C1/C2. У каждого есть значение, шкала и определение. Все значения от 0 до 100, больше — лучше.
- У каждого направления есть общий балл и полоска даже в свёрнутом виде. Общий балл нормализован на 0–100 с весами модели: экология = 45% E1 + 55% E2, у остальных пар равные веса. После применения мер общий балл, подпоказатели и D показывают численные изменения относительно начала раунда. Синий — сохранённая часть, зелёный — прирост, красный — потеря; при снижении красный сегмент заканчивается на исходном значении, число рядом показывает текущее.
- Индекс района D рассчитывается с весами модели, а не простым средним. Карта показывает тот же D.
- На широком экране слева высокая панель статистики, справа сверху компактный бюджет и счётчик, снизу справа — действия. Панели не перекрываются. На узком экране действия занимают нижнюю полосу, статистика располагается выше.
- Внизу — горизонтальные вкладки категорий и компактные карточки действий. «Весь город» содержит M2, M6, M12, M14; остальные вкладки — только районные меры.
- На карточке слева название и район (или весь город), справа стоимость. Эффекты и лаг заранее не показываются. Причины недоступности остаются видны сразу.
- Блок «О раунде» убран. Описания — в «О районе и показателях», список выбранных мер, удаление черновика и сброс — в «План».
- Можно выбрать и применить одну или несколько мер за отправку. Применённые меры сохраняются; черновик можно удалить до отправки.
- Всего за раунд нужно применить ровно 5 уникальных мер. Бюджет общий: 100, максимум 2 меры исходного направления, все несовместимости действуют между отправками. «Весь город» не является отдельным направлением для этого лимита.
- Показатели карты и района учитывают только применённые меры. Бюджет сверху учитывает также зарезервированные в черновике.
- После отправки карточки исчезают: вместо них вкладки направлений с зелёными/красными дельтами и объяснением. Здесь изменения только за последнюю отправку; левая статистика по-прежнему сравнивает с началом раунда. До пятого решения кнопка «Следующее действие» возвращает карточки.
- После пятого решения доступно итоговое окно: Score до/после, направления по городу с учётом населения, улучшения/ухудшения, критичные показатели, поздравление и новый раунд. Таблица районов и число неизменившихся показателей здесь не показываются. Если отправлены сразу все пять, сначала показывается результат хода, а окно открывается только по кнопке «Итоги раунда». При завершении поэтапного раунда оно открывается автоматически. Шестое решение заблокировано.
- «Почему изменилось» — отдельный блок GPT после хода и в итогах раунда, не более 50 слов. Текст загружается независимо от расчёта; ошибки API не блокируют игру. Сервер и интерфейс ограничивают длину, устаревшие ответы после следующего хода или сброса игнорируются.
- Кнопка «Обновить отчёт» повторно запрашивает объяснение после успеха или ошибки, не применяя меры заново и не меняя бюджет, Score или число решений. Во время запроса повторное нажатие заблокировано.
- В ожидании GPT показываются строка «Идёт стройка по вашим решениям…», анимация зданий и движущаяся полоска без вымышленных процентов. После ответа или ошибки они исчезают; при `prefers-reduced-motion` остаётся статичный индикатор.
- Закрытие района не сбрасывает выбор. Раунд хранится в памяти вкладки; перезагрузка страницы начинает новый.
- Ошибка сервера сохраняет черновик и ранее применённые решения для повторной отправки.

## Данные и формула

Стартовые значения: `src/simulator/districts.ts`. Каталог с эффектами и лагами: `src/simulator/measures.ts`. Русские подписи и определения: `src/simulator/presentation.ts`.

Есиль — богатый, с пробками на мостах и переполненными школами; Алматы — старый ЖКХ и пробки; Сарыарка — смог от частного сектора и слабое озеленение; Байконур — без ярких перекосов; Нура — слабая соцсфера и транспорт. Это игровые данные, не городская статистика.

Исходные D: Есиль 62.99, Алматы 57.06, Сарыарка 54.65, Байконур 56.63, Нура 49.18.

```text
I' = clip(I + сумма эффектов × (8 − лаг) / 8 + фиксированные синергии, 0, 100)
D = сумма вес × показатель
Score = 0.7 × средневзвешенный D + 0.3 × минимальный D − число показателей <40
```

Базовый Score: **52.55768**. Пример M7/M8/M10 в Нуре, M12 для города, M5 в Сарыарке: стоимость **95**, Score **56.54307**, прирост **3.98539**. Пример M9 + M11 + M10 + M12 + M4 валиден и стоит **61**.

Сарайшык не получает отдельные показатели или долю населения: объединённая территория использует модель Алматы.

## Backend

Интерфейс вызывает серверную функцию `simulateCity` из `src/server/simulateCity.ts`:

```ts
simulateCity({ data: { actions: [
  { measureId: 'M7', district: 'Nura' },
  { measureId: 'M12' },
] } })
```

Каждая отправка содержит весь накопленный набор. Сервер заново считает его от исходных данных: повторы запроса не удваивают эффекты и расходы. Район обязателен для районной меры и запрещён для городской. Сервер проверяет IDs, бюджет, повторы, направления и конфликты, не доверяя клиентским числам.

- Частичный набор: `{ ok: true, complete: false, result }`; поля `districts`, `budget`, `actions`, `horizon`, `synergies`, без итогового Score.
- Полный набор: `{ ok: true, complete: true, result }`; полный расчёт и разбивка Score без ожидания GPT.
- Ошибка: `{ ok: false, error }`, без изменения состояния интерфейса.

Отдельная функция `explainCityActions({ data: { actions, previousActions } })` возвращает `{ step, round }`, где каждое объяснение содержит `aiAnalysis` / `aiError`. `round` присутствует только для пяти мер. Сервер проверяет, что предыдущие меры — корректное подмножество текущих, и сам рассчитывает дельты последней отправки. Для полного раунда GPT отдельно получает весь итог. Ключ `OPENAI_API_KEY` нужен только на сервере; без него показывается аккуратное сообщение о недоступности объяснения. Числа остаются результатом детерминированного расчёта.

`simulate()` остаётся строгим расчётом ровно пяти мер; `simulateProgress()` обслуживает промежуточные отправки. Подробности разбивки — в [src/simulator/README.md](src/simulator/README.md). LLM объясняет готовые числа, но не рассчитывает их.

## Карта

Границы загружаются из Places API 2ГИС для города `9570771978420226`; WKT Polygon/MultiPolygon преобразуется в геометрию. Улицы, здания, вода, парки и атрибуция сохранены. Фон светлый: `src/lib/map-style.ts` заменяет только фоновые слои. Для собственного опубликованного стиля задайте `VITE_2GIS_MAP_STYLE_ID`; тогда встроенная перекраска отключается.

Ошибки карты/границ имеют кнопку повторной загрузки. Перемещение и масштабирование доступны. Нижняя панель и левая статистика учтены при центрировании карты.
